# 06. モックデータとデモシナリオ

## 1. モックデータの原則

- 実在人物の個人情報を使わない
- 実在サービスの認証コード、購入情報、メールアドレスを使わない
- すべてローカルで完結させる
- 同じ操作で同じ結果になる決定的なデータを使う
- デモの初期化ができるようにする

## 2. 基本フィクスチャ

### 祖父

```ts
{
  id: 'grandfather-1',
  displayName: 'おじいちゃん',
  online: true
}
```

### 家族

```ts
{
  id: 'family-1',
  displayName: '家族'
}
```

### 支援依頼

```ts
{
  id: 'request-auth-code',
  screenshotId: 'mock-mail-screen',
  comment: '番号は分かったけれど、飛行機の画面に戻れません'
}
```

### ガイド

主シナリオで使用するガイド：

```text
認証コードを確認したあと、元の画面へ戻る
```

手順：

1. 画面下のタスクバーを見ます。
2. 飛行機の購入画面のアイコンを押します。
3. 元の画面に戻ったら、控えた番号を入力します。

一覧の選択操作を確認するため、追加のダミーガイドを置いてよい。ただし、主シナリオを目立たせること。

## 3. ダミー画面

最低限、次の画面を用意する。

- `mock-mail-screen`：認証コードを確認したあとのメール画面
- `mock-taskbar-screen`：タスクバーと購入画面アイコンが見える画面
- `mock-purchase-screen`：購入画面へ戻り、番号入力欄がある画面

画像ファイルでなく、HTML/CSSで構成してもよい。

## 4. デモシナリオ

### Scenario A：支援してガイドを作る

設定：

- 類似ガイド：なし
- 祖父：オンライン

手順：

1. 祖父側で左端パネルを開く
2. 困りごとを記録する
3. コメントを入力して送る
4. 類似ガイドなしとなる
5. 家族側で通知を見る
6. 支援依頼を開く
7. 家族が電話をかける
8. 祖父が電話に出る
9. 家族が共有画面のタスクバー付近をクリックする
10. 祖父側へマーカーが表示される
11. 疑似記録件数が増える
12. 問題を解決した状態へ進める
13. ガイド作成を選ぶ
14. 家族がタイトルまたは説明文を編集する
15. 祖父側で変更を確認する
16. 保存する
17. 接続が終了する
18. 保存済みガイドが一覧にあることを確認する

### Scenario B：類似ガイドを使って解決する

設定：

- 類似ガイド：あり

手順：

1. 祖父側で困りごとを記録する
2. 類似ガイド確認中を表示する
3. 該当ガイドへ移る
4. 1ステップずつ進める
5. `できました` で完了する

### Scenario C：一覧からガイドを使う

1. 祖父側で左端パネルを開く
2. `ガイドを見る` を押す
3. 一覧から主シナリオのガイドを選ぶ
4. 前後に移動する
5. 最終ステップで完了する

### Scenario D：ガイド途中から家族に相談する

1. Scenario BまたはCでガイドを開始する
2. 任意の途中ステップで `遠隔支援へ移る` を押す
3. 確認後、支援依頼作成へ移る
4. 家族側に依頼が表示されるところまで確認する

## 5. デモコントロール

`/demo` の開発用領域に次を置く。

- シナリオ選択
- 類似ガイドの有無
- 祖父のオンライン / オフライン
- 疑似生成待ち時間の短縮切り替え
- 現在状態表示
- イベントログ
- リセット

オフライン時の完全な異常系は今回実装しなくてよい。状態表示と、発信を無効にできれば十分である。

## 6. 疑似時間

- ガイド照合：300〜800ms程度
- 接続中：300〜800ms程度
- 仮ガイド生成：500〜1200ms程度
- 支援中の疑似記録：5秒ごと

テストではタイマーを制御し、実時間を待たない。

## 7. 保存

- ガイド保存はローカルストアへ行ってよい
- リセット時に初期フィクスチャへ戻す
- 支援中の疑似スクリーンショットは実画像として永続化しない
