# Mite 仕様探索用プロトタイプ

Mite（ミテ）は、高齢のPC利用者が、離れて暮らす家族から操作の案内を受ける体験を検証するためのプロトタイプです。祖父本人ができる操作は本人に任せ、家族は音声案内と画面上のマーカーで「次に何をするか」を伝える想定です。

このリポジトリは仕様探索用であり、本番アプリではありません。Windows画面の取得、デスクトップへのオーバーレイ、通知、音声通話、ネットワーク越しの画面共有、AIによるガイド生成、オンライン判定、サーバー保存はすべて画面内のモックです。画面・マイク・カメラの権限は要求せず、入力内容を外部サービスへ送信しません。

## 起動方法

Node.js と npm が利用できる環境で、次を実行します。

```sh
npm install
npm run dev
```

ターミナルに表示されたローカルURLをブラウザで開き、`/demo` へ移動します。通常は `http://localhost:5173/demo` です。

## 画面

- `/demo`: 祖父側と家族側を一画面に並べた、正常系の確認に推奨する画面です。両者は同じ状態を共有するため、一つのタブだけで最初から最後まで試せます。
- `/grandfather`: 祖父側だけを表示します。メール画面を模した画面、支援依頼、着信、案内中のマーカー、ガイド確認を体験できます。
- `/family`: 家族側だけを表示します。支援依頼の確認、発信、共有画面へのマーカー、支援終了、ガイド編集を体験できます。

`/grandfather` と `/family` を別タブで開いた場合は、`BroadcastChannel` と `localStorage` フォールバックによって同じブラウザ内で疑似同期します。これはネットワーク通信ではありません。複数端末や異なるブラウザ間では同期しません。

## `/demo` のデモ手順

題材は「認証コードをメールで確認したあと、航空券の購入画面へ戻れなくなった」です。

1. `/demo` を開きます。以前の状態が残っている場合は、開発用表示にある「最初からやり直す」を押します。
2. 祖父側の画面左端にある細いバーへマウスを移動し、展開した支援パネルで「困りごとを記録する」を押します。
3. メール画面を記録した体のプレビューを確認し、必要ならコメントに「番号は分かったけれど、飛行機の画面に戻れません」と入力して支援依頼を送ります。
4. 短いモック遅延のあと、家族側に届いた支援依頼を開きます。記録時刻、コメント、ダミー画像と、祖父が「オンライン」であることを確認します。
5. 家族側から祖父へ電話をかけます。祖父側に表示された着信で「電話に出る」を押します。
6. 短い接続中表示のあと、両側が支援中になります。音声通話中という表示はありますが、実際の音声は送受信されません。
7. 家族側の共有画面で、画面下のタスクバーにある航空券購入画面のアイコン付近をクリックします。家族側と祖父側の同じ位置に目立つマーカーが表示されることを確認します。これは遠隔操作ではなく、クリック位置を示すだけです。
8. 家族側で支援を終了し、「ガイドを作成する」を選びます。「作成しない」を選ぶ分岐では、そのまま終了することも確認できます。
9. 固定のひな形から作られた仮ガイドのタイトルと3つの手順を家族側で編集し、祖父に確認を依頼します。
10. 祖父側に読み取り専用で表示されたガイドを確認します。家族側でガイドを保存して支援を終了します。
11. 完了表示と直近イベントを確認し、「最初からやり直す」で初期状態へ戻れることを確認します。

途中の短い待機表示は、通知配送と接続確立を模した自動遷移です。仮ガイドは固定のひな形であり、実サービスやAIには接続していません。

## 開発用表示

画面には、仕様探索のために現在の支援状態と直近イベントを表示します。利用者向けの最終UIではなく、「どの操作でどの状態へ移ったか」を確認するための表示です。リセットもここから実行できます。

主な状態は `idle`、`requestDraft`、`requestSent`、`waitingForFamily`、`familyViewingRequest`、`incomingCall`、`connecting`、`inSession`、`guideDecision`、`guideDraft`、`guideReview`、`completed` です。

## コマンド

```sh
npm run dev
npm run build
npm run test
npm run lint
```

- `dev`: Vite 開発サーバーを起動します。
- `build`: TypeScript の検査と本番向けバンドルを行います。
- `test`: 状態遷移と正常系の単体テストを実行します。
- `lint`: ソースコードの静的検査を実行します。

## プロトタイプの前提

- データは架空の固定データです。実際の個人情報や画面データを入力しないでください。
- 状態遷移はクライアント内の reducer に集約し、UIはイベントを送る形にしています。
- `/demo` は単一の共有状態、個別ルート間はブラウザ内の疑似同期を使います。
- リロード後の状態保持や複数タブ競合は、本番品質を保証するものではありません。
- React、TypeScript、Vite を使うことはプロトタイプ上の仮決定であり、将来のWindowsアプリの技術選定ではありません。
- 未決定の仕様は [docs/open-questions.md](docs/open-questions.md)、プロトタイプ上の仮決定は [docs/decisions.md](docs/decisions.md) に記録しています。
