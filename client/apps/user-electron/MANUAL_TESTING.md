# 利用者側の画面共有・マーキング・端末保存

Windows 11の利用者PCと家族PCで、[セットアップ手順](../../../docs/setup.md)に従って確認する。
WSL上の単体テストでは、Windowsのデスクトップ表示と撮影除外は確認できない。

## 正常系

1. 利用者が相談を送り、家族が発信し、利用者が「同意して応答する」を1回押すと、音声と画面全体の共有が始まり、メニューがしまわれる。
2. 家族に映像が届き、利用者側も「画面全体を共有中」と表示されることを確認する。
3. 利用者側の保存枚数が開始直後に1枚となり、その後10秒ごとに増えることを確認する。
   利用者アプリの出力に `capture:initialize` の `EPERM` とファイルハンドル未解放の警告が出ないことも確認する。
4. 家族側で共有映像の中央と四隅付近をクリックする。利用者の実際の操作画面上に丸が出て、2秒後に消えることを確認する。
5. 利用者がMiteのパネルを「しまう」で閉じても丸が表示され、丸の位置にある他アプリのボタンをクリックできることを確認する。
6. 家族側の映像と保存されたJPEGに、Miteのパネルと丸・カーソル・マウス・キー案内が含まれないことを確認する。
7. 共有を停止すると丸が消え、映像と定期取得が停止することを確認する。再開後は新しい案内が表示され、ACTIVEの場合だけ保存枚数が続きから増えることを確認する。
8. 家族がガイド作成へ進むと定期撮影と共有が止まり、画像送信・生成・編集の間は音声が続くことを確認する。レビュー完了で全ガイドが保存され、支援・通話・案内が終了することを確認する。

## 画面設定・配布物

- プライマリ画面を複数画面構成の左右それぞれに配置して、マーキングがプライマリ画面にだけ表示されることを確認する。
- 表示倍率100%、150%、200%とタスクバーの配置を変えて、丸と操作対象の位置を確認する。設定変更時に古い丸が消えることも確認する。
- アプリ終了後にマーキング用ウィンドウが残らず、既存の左端4pxの予約が解除されることを確認する。
- Windowsの `client/` で `npm run make:user` を実行し、配布版でも同じ手順を確認する。

## 自動テストが確認する失敗時の動作

- ファイル書き込み・同期が失敗してもハンドルを閉じ、直前のmanifestを保持する。
- 保存初期化が失敗しても通話・画面共有・マーキングを継続し、保存は10秒後に再試行する。
- ガイド送信前の端末保存エラーを通信エラーと区別し、再試行後に処理を進める。
- 別の映像トラックのマーキングを無視し、共有停止・支援終了・表示期限切れで丸を消す。

## 操作案内・メニュー・音声

- カーソルとマウスのモードで、左・右・中央ボタン、押し続ける操作、ドラッグとドロップが見えることを確認する。
- キーボードのモードで共有画面へフォーカスし、Ctrl+Cなどの同時キーを表示する。Shift+Escで案内を抜けられること、モード切替・フォーカス離脱・切断時に古い押下表示が残らないことを確認する。
- ガイド実行以外ではMiteの外側をクリックしてしまい、左端から入力中の画面へ直接戻る。入力内容、表示中の手順、通話・共有・操作案内が保持されることを確認する。
- 利用者PCのスピーカーが50%未満なら50%に上がり、50%以上では変わらないことを確認する。双方の自分のマイクのメーターと、通話開始からの経過時間を確認する。
- 家族側を最大化して終了し、次回も最大化することを確認する。

これらの実機操作は今回の自動検証の完了条件には含めない。自動テストの結果は[対応記録](../../../docs/family-support-improvements.md)を参照する。

## ガイドの小窓・途中終了・待ち時間

- ガイド使用時に小窓が他アプリの上へ表示され、上部をドラッグして移動できることを確認する。他アプリをクリックしても閉じず、ボタンはドラッグせずに押せることを確認する。
- 100%、150%、200%の表示倍率、プライマリ画面の変更、タスクバーの位置変更後も小窓全体が作業領域内に収まり、左端のAppBar予約が4pxのままであることを確認する。最大化した他アプリの作業領域、終了時の予約解除も確認する。
- 最終手順より前に「途中で終了する」を押すと一覧へ戻り、再度同じガイドを始めると手順1になることを確認する。通信を遮断した場合は小窓を保持し、復旧後の再試行で終了できることを確認する。
- 短いクリック・打鍵とCtrl+Cの部分解放でも押下の案内が最低1秒見えることを確認する。長押しは解放まで続き、「案内を消す」・共有停止・切断では即座に消えることを確認する。
- 画像が複数ある支援からGemini生成を行う。サーバーの `guide generation attempt` に記録される `inputMs` と `generationMs` で画像準備と生成の時間を分けて確認する。HTTP要求上限と画像準備込みの処理上限はともに300秒とし、HTTP要求は画像準備後の残り時間以内に打ち切られることを確認する。
- 同じ画像を短時間に再表示した場合に再取得を省けることと、応答から配信開始までの時間を2台のWindows実機で確認する。

Windows 11のElectronで、別ウィンドウの最大化・フォーカス移動後もガイドが表示されること、位置変更後の再計算、範囲外位置の補正、AppBarの4px予約と終了後の作業領域の復元を自動確認した。架空の画面31枚（JPEG合計1,148,240バイト）による実Gemini API接続では、約24秒でガイド1件の生成と形式検証に成功した。これは合成画像による1回の測定であり、実際の支援画像での生成時間、マウスによるドラッグ、DPI・タスクバー設定変更、2台接続での配信時間は未確認である。DBには `20260910000100_cancel_guide_run.sql` まで適用し、サーバーと利用者アプリを更新してから確認する。

Windows上で `npm run make:user` と `npm run make:family` は成功した。配布物はそれぞれのアプリの `out/make/squirrel.windows/x64/` に出力される。
